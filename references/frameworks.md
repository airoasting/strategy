## 문제 해결·사고 도구 (11개)

### #1. 이슈 트리 / MECE (Issue Tree / MECE Framework)
- 한 줄: 맥킨지의 핵심 문제 구조화 도구입니다.
- 쓸 때: 복잡한 전략 문제의 초기 구조화; 핵심 이슈와 그 원인을 체계적으로 분해할 때; 팀원들이 같은 문제 지도를 공유해야 할 때; 가설을 세우고 분석 계획을 짤 때
- 뼈대: 핵심 질문 (Key Question) · 트리의 뿌리, 해결해야 할 단 하나의 문제 / 이슈 (Issues) · MECE하게 분해된 하위 질문 / MECE 원칙 · 상호 배타(중복 없음) + 전체 포괄(누락 없음) / 가설 (Hypothesis) · 각 이슈에 대한 잠정 답변 / 증거 (Evidence) · 가설을 검증하는 데이터와 분석
- 단계: 핵심 질문(Key Question)을 한 문장으로 명확히 정의합니다. → 핵심 질문을 MECE하게 1차 이슈로 분해합니다 (2~5개). → 각 1차 이슈를 다시 MECE하게 2~3차로 분해합니다. → 각 말단 이슈에 가설을 세웁니다. → 가설 검증에 필요한 분석을 정의합니다. → 분석 결과로 트리를 거슬러 올라가며 핵심 질문에 답합니다. → 피라미드 원칙으로 결론→근거→데이터 순으로 커뮤니케이션합니다.
- 한계: MECE 분해 기준이 잘못 설정되면 전체 트리가 왜곡됩니다. 너무 빠르게 분해에 집중하면 진짜 핵심 질문 정의를 놓칩니다. 트리 자체가 아니라 각 이슈의 가설 검증이 더 중요합니다.
- 빈도 ★★★★★ · 효과 ★★★★★
- 갤러리 관련: #36 Balanced Scorecard, #2 시나리오 플래닝, #52 프로세스 분해
- 카드: https://strategy.airoasting.com/#1

### #2. 시나리오 플래닝 (Scenario Planning)
- 한 줄: 불확실성이 높은 환경에서 전략을 설계하는 도구입니다.
- 쓸 때: 불확실성이 매우 높은 거시 환경 변화에 대응할 때; 5~10년 장기 전략 수립; 기술·규제·지정학 변수가 큰 산업; 단일 예측보다 복수 시나리오 준비가 필요할 때
- 뼈대: 핵심 드라이버 · 미래를 가장 크게 바꿀 2개의 불확실한 변수 / 4개 시나리오 · 드라이버 조합으로 만들어지는 미래 상황 / 시나리오 스토리 · 각 미래의 세부 묘사 / 선행 지표 (Early Indicators) · 어느 시나리오로 가고 있는지 알려주는 신호 / 전략 옵션 · 각 시나리오에 맞는 사전 대응
- 단계: 전략적 핵심 질문을 정의합니다. → 환경을 스캔해 핵심 드라이버 후보를 도출합니다. → 가장 불확실하고 영향이 큰 드라이버 2개를 선정합니다. → 2×2로 4가지 시나리오를 설계하고 이름을 붙입니다. → 각 시나리오에 스토리와 세부 묘사를 작성합니다. → 각 시나리오의 선행 지표를 정의합니다. → 각 시나리오에서 유효한 전략 옵션과 공통 전략을 도출합니다.
- 한계: 시나리오가 실제 미래와 다를 수 있고, 4가지 이외 미래는 다루지 않습니다. 드라이버 선정 자체가 전략적 판단이어서 편향이 개입됩니다. 도출한 전략을 실제로 준비하지 않으면 의미가 없습니다.
- 빈도 ★★★☆☆ · 효과 ★★★★★
- 갤러리 관련: #1 이슈 트리 / MECE, #16 PEST(EL) 분석, #13 5 Forces 분석
- 카드: https://strategy.airoasting.com/#2

### #3. 피라미드 원칙 (Pyramid Principle / SCQA)
- 한 줄: 핵심 결론을 먼저 말하고 근거를 피라미드 구조로 쌓는 맥킨지 표준 커뮤니케이션 프레임입니다.
- 쓸 때: 임원 보고·PT에서 메시지를 명확히 전달해야 할 때; 복잡한 분석 결과를 슬라이드 한 장으로 정리해야 할 때; 팀원에게 분석 방향을 구조적으로 지시해야 할 때; 이메일·메모로 의사결정을 요청할 때
- 뼈대: SCQA · Situation(상황) → Complication(핵심 문제) → Question(질문) → Answer(답) / 피라미드 정점 · 단 하나의 핵심 메시지 (So What?) / 키 라인 · 정점을 지지하는 2~4개 논거 (Why So?) / 서포팅 · 각 논거를 뒷받침하는 데이터·사실 / MECE · 각 레이어 내 항목은 서로 겹치지 않고 전체를 포괄
- 단계: So What을 먼저 씁니다. 독자가 이 문서에서 취해야 할 행동이나 판단이 무엇인지 한 문장으로 정합니다. → SCQA로 도입부를 구성합니다. 현재 상황, 문제 발생, 질문, 답의 순서로 이야기를 엮습니다. → 핵심 메시지를 지지하는 논거 2~4개를 MECE하게 나눕니다. → 각 논거 아래에 데이터·사례·분석을 배치합니다. → 위에서 아래로 읽어도, 아래에서 위로 읽어도 논리가 성립하는지 검토합니다. → 슬라이드라면 제목 줄이 "So What"이 되도록 씁니다.
- 한계: 결론을 먼저 제시하는 방식이 문화적으로 낯선 조직에서는 저항감이 생길 수 있습니다. 근거가 부실하면 피라미드가 무너지므로 분석이 먼저 완료되어야 합니다. 창의적·탐색적 논의에는 맞지 않습니다.
- 빈도 ★★★★☆ · 효과 ★★★★★
- 갤러리 관련: #1 이슈 트리 / MECE, #2 시나리오 플래닝
- 카드: https://strategy.airoasting.com/#3

### #4. 디자인 씽킹 (Design Thinking (IDEO 5단계))
- 한 줄: 사용자 공감에서 출발해 시제품 테스트까지 5단계로 혁신 해법을 찾는 인간 중심 프로세스입니다.
- 쓸 때: 사용자 니즈가 불명확하고 문제 정의가 필요한 상황; 혁신적 해법이 필요한 복잡한 문제; 기존 솔루션이 효과 없을 때 전혀 다른 접근이 필요한 경우; 고객 경험(CX) 재설계 프로젝트
- 뼈대: Empathize (공감) · 사용자를 관찰·인터뷰하여 진짜 니즈를 이해 / Define (문제 정의) · "어떻게 하면 …할 수 있을까?(HMW)" 형태로 문제 재정의 / Ideate (아이디어 발산) · 브레인스토밍으로 다양한 해결책 도출 / Prototype (시제품) · 빠르고 저렴하게 아이디어를 실물화 / Test (테스트) · 실제 사용자에게 프로토타입을 검증하고 반복
- 단계: [Empathize] 현장 관찰과 인터뷰로 사용자의 행동·감정·불만을 기록합니다. → [Define] 공감 결과를 분석해 "HMW(어떻게 하면 …할 수 있을까?)" 문장으로 문제를 정의합니다. → [Ideate] 판단 없이 최대한 많은 아이디어를 냅니다. 양이 질을 이깁니다. → [Prototype] 상위 아이디어를 빠르게 시제품(종이 목업, 서비스 시나리오 등)으로 만듭니다. → [Test] 사용자에게 프로토타입을 경험하게 하고 피드백을 수집합니다. → 피드백을 바탕으로 Define 또는 Ideate 단계로 돌아가 반복합니다.
- 한계: 시간이 충분하지 않으면 공감 단계가 생략되어 표면적 해결책에 그칩니다. 실행 및 확장을 위한 비즈니스 타당성 검토는 별도 분석이 필요합니다. 참여자들이 방법론에 익숙하지 않으면 퍼실리테이터가 필요합니다.
- 빈도 ★★★☆☆ · 효과 ★★★★☆
- 갤러리 관련: #52 프로세스 분해, #24 Jobs-to-be-Done, #23 Customer Journey Map
- 카드: https://strategy.airoasting.com/#4

### #5. 5 Whys (Five Whys)
- 한 줄: 왜를 다섯 번 물어 근본 원인을 찾는 도구입니다.
- 쓸 때: 단일 문제의 근본 원인을 빠르게 찾을 때; 품질 결함이나 사고의 재발을 막아야 할 때; 복잡한 분석 도구 없이 현장에서 즉시 파고들 때; 증상 대응이 아닌 구조적 해결책이 필요할 때
- 뼈대: 문제 정의 (Problem Statement) / 연속된 왜 질문 (Why Chain) / 인과 연결 (Cause-Effect Link) / 근본 원인 (Root Cause) / 대응책 (Countermeasure)
- 단계: 문제를 구체적인 사실로 정의합니다. → '왜 이 문제가 발생했는가'를 묻습니다. → 답에 다시 '왜'를 묻습니다. → 인과 관계가 끊기지 않는지 확인하며 반복합니다. → 보통 다섯 번 반복해 근본 원인에 도달합니다. → 근본 원인에 맞는 대응책을 설계합니다. → 대응책 실행 후 재발 여부를 검증합니다.
- 한계: 답을 한 줄기로만 따라가 다중 원인을 놓칠 수 있습니다. 분석자의 지식과 가정에 결과가 크게 좌우됩니다. 복잡한 시스템 문제에는 깊이가 부족합니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆
- 갤러리 관련: #6 특성요인도, #55 DMAIC, #58 PDCA 사이클
- 카드: https://strategy.airoasting.com/#5

### #6. 특성요인도 (Fishbone / Ishikawa Diagram)
- 한 줄: 하나의 결과에 영향을 주는 원인을 생선뼈 형태로 분류하는 도구입니다.
- 쓸 때: 한 문제의 다양한 원인을 빠짐없이 도출할 때; 팀이 브레인스토밍으로 원인을 함께 정리할 때; 품질 결함의 원인 범주를 체계화할 때; 근본 원인 분석에 앞서 가설 후보를 펼칠 때
- 뼈대: 문제 (Head) / 주요 원인 범주 (Main Bones) / 6M (Man/Machine/Method/Material/Measurement/Environment) / 세부 원인 (Sub-causes) / 핵심 원인 후보
- 단계: 분석할 문제를 생선 머리에 명확히 적습니다. → 주요 원인 범주를 큰 뼈대로 설정합니다. → 6M 같은 표준 범주를 활용합니다. → 각 범주별로 세부 원인을 브레인스토밍합니다. → 세부 원인에 다시 하위 원인을 붙입니다. → 영향이 큰 핵심 원인 후보를 표시합니다. → 데이터로 핵심 원인을 검증합니다.
- 한계: 원인을 나열할 뿐 원인 간 우선순위는 보여주지 못합니다. 범주 설정이 부적절하면 중요한 원인을 빠뜨립니다. 데이터 검증 없이 추정에 머물 위험이 있습니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆
- 갤러리 관련: #5 5 Whys, #7 파레토 분석, #1 이슈 트리 / MECE
- 카드: https://strategy.airoasting.com/#6

### #7. 파레토 분석 (Pareto Analysis (80/20))
- 한 줄: 소수의 핵심 원인이 대부분의 결과를 만든다는 80/20 도구입니다.
- 쓸 때: 여러 문제 중 무엇부터 해결할지 정할 때; 한정된 자원을 핵심 영역에 집중할 때; 불량·클레임·매출 기여를 우선순위화할 때; 개선 효과가 큰 소수 항목을 찾아낼 때
- 뼈대: 분석 대상 항목 (Categories) / 빈도/금액 데이터 / 내림차순 막대 / 누적 비율 곡선 / 80% 기준선 / 핵심 소수 (Vital Few)
- 단계: 분석할 문제와 항목을 정의합니다. → 항목별 빈도나 금액 데이터를 수집합니다. → 값이 큰 순서로 항목을 정렬합니다. → 누적 비율을 계산합니다. → 막대와 누적 곡선으로 파레토 차트를 그립니다. → 누적 80%에 드는 핵심 소수를 식별합니다. → 핵심 소수에 개선 자원을 집중합니다.
- 한계: 80/20은 경향일 뿐 모든 상황에 들어맞지는 않습니다. 과거 데이터에 기반해 새로운 위험을 놓칠 수 있습니다. 빈도가 낮아도 치명적인 문제를 과소평가할 수 있습니다.
- 빈도 ★★★★★ · 효과 ★★★★☆
- 갤러리 관련: #6 특성요인도, #1 이슈 트리 / MECE, #31 이익 방정식
- 카드: https://strategy.airoasting.com/#7

### #8. 6색 사고모자 (Six Thinking Hats)
- 한 줄: 여섯 색 모자로 사고의 관점을 전환하며 회의하는 도구입니다.
- 쓸 때: 회의에서 다양한 관점을 균형 있게 다룰 때; 감정과 논리가 뒤섞인 논의를 정리할 때; 집단사고나 한쪽 의견 쏠림을 막을 때; 아이디어를 다각도로 검토하고 결론을 낼 때
- 뼈대: 흰 모자 (사실/데이터) / 빨강 모자 (감정/직관) / 검정 모자 (위험/비판) / 노랑 모자 (이익/긍정) / 초록 모자 (창의/대안) / 파랑 모자 (진행/통제)
- 단계: 논의 주제와 목표를 파랑 모자로 설정합니다. → 흰 모자로 사실과 데이터를 공유합니다. → 빨강 모자로 직관과 감정을 표현합니다. → 노랑 모자로 이점과 가능성을 봅니다. → 검정 모자로 위험과 약점을 점검합니다. → 초록 모자로 새로운 대안을 모색합니다. → 파랑 모자로 정리하고 결론을 도출합니다.
- 한계: 진행자의 역량에 회의 품질이 크게 좌우됩니다. 형식에 익숙하지 않으면 어색하고 인위적으로 느껴집니다. 분석 도구가 아니라 토론 진행 보조 수단에 가깝습니다.
- 빈도 ★★★☆☆ · 효과 ★★★☆☆
- 갤러리 관련: #4 디자인 씽킹, #1 이슈 트리 / MECE, #2 시나리오 플래닝
- 카드: https://strategy.airoasting.com/#8

### #9. 아이젠하워 매트릭스 (Eisenhower Matrix)
- 한 줄: 긴급도와 중요도 두 축으로 할 일의 우선순위를 가르는 시간 관리 도구입니다.
- 쓸 때: 할 일이 쌓여 우선순위가 흐려졌을 때; 긴급한 일에 떠밀려 중요한 일을 놓칠 때; 팀 업무를 위임·제거 기준으로 정리할 때; 개인이나 팀의 시간 배분을 점검할 때
- 뼈대: 긴급도 축 (Urgency) / 중요도 축 (Importance) / 제1사분면 즉시 실행 (긴급+중요) / 제2사분면 계획 수립 (중요+비긴급) / 제3사분면 위임 (긴급+비중요) / 제4사분면 제거 (비긴급+비중요)
- 단계: 처리해야 할 모든 업무를 빠짐없이 나열합니다. → 각 업무의 긴급도를 '지금 해야 하는가' 기준으로 평가합니다. → 각 업무의 중요도를 '목표에 기여하는가' 기준으로 평가합니다. → 두 축의 조합에 따라 업무를 4사분면에 배치합니다. → 제1사분면은 즉시 처리하고, 제2사분면은 일정에 못박습니다. → 제3사분면은 위임 대상을 정하고, 제4사분면은 과감히 제거합니다. → 주기적으로 매트릭스를 갱신해 분면 쏠림을 점검합니다.
- 한계: 긴급도와 중요도 판단이 주관적이라 사람마다 분류가 달라집니다. 모든 일이 '중요'로 분류되면 변별력이 사라집니다. 업무 간 의존 관계나 소요 시간은 반영하지 못합니다.
- 빈도 ★★★★★ · 효과 ★★★★☆
- 갤러리 관련: #42 SMART 목표, #1 이슈 트리 / MECE, #39 OKR
- 카드: https://strategy.airoasting.com/#9

### #10. 리스크 매트릭스 (Risk Matrix (Probability-Impact))
- 한 줄: 발생 확률과 영향도 두 축으로 위험을 등급화해 대응 우선순위를 정하는 도구입니다.
- 쓸 때: 프로젝트 착수 전 위험을 식별하고 분류할 때; 한정된 자원으로 위험 대응 순서를 정해야 할 때; 경영진에게 위험 현황을 한눈에 보고할 때; 정기적으로 위험 상태 변화를 추적할 때
- 뼈대: 발생 확률 축 (Probability) / 영향도 축 (Impact) / 리스크 점수 (확률 x 영향) / 위험 등급 구간 (낮음/중간/높음) / 대응 전략 (회피/전가/완화/수용) / 리스크 등록부 (Risk Register)
- 단계: 프로젝트나 사업의 잠재 위험을 빠짐없이 식별합니다. → 각 위험의 발생 확률을 등급이나 점수로 평가합니다. → 각 위험이 발생했을 때의 영향도를 평가합니다. → 확률과 영향을 곱해 리스크 점수를 산출합니다. → 점수에 따라 매트릭스 격자에 배치하고 색상으로 등급을 표시합니다. → 고위험 구간부터 회피·전가·완화·수용 대응 전략을 정합니다. → 리스크 등록부에 책임자와 일정을 기록하고 주기적으로 갱신합니다.
- 한계: 확률과 영향 평가가 정성적이라 평가자 편향에 취약합니다. 동일 점수라도 성격이 다른 위험을 같게 다룰 수 있습니다. 식별하지 못한 위험은 매트릭스에 아예 나타나지 않습니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆
- 갤러리 관련: #9 아이젠하워 매트릭스, #2 시나리오 플래닝, #65 간트 차트
- 카드: https://strategy.airoasting.com/#10

### #70. OODA 루프 (OODA Loop (Observe-Orient-Decide-Act))
- 한 줄: 관찰-판단-결정-행동을 빠르게 돌려 상대보다 먼저 의사결정하는 도구입니다.
- 쓸 때: 경쟁사보다 빠른 의사결정 속도가 승부를 가르는 상황; 시장·기술·경쟁이 빠르게 변해 장기 계획이 금세 낡는 환경; 위기 대응·실시간 운영에서 즉각적인 판단이 필요할 때; 스타트업이 대기업의 느린 의사결정을 속도로 이기려 할 때
- 뼈대: Observe (관찰) · 환경·경쟁·고객의 변화 신호를 실시간으로 수집 / Orient (판단) · 수집한 정보를 기존 정신 모델·경험에 비춰 재해석 (가장 중요) / Decide (결정) · 재해석을 바탕으로 행동 가설을 선택 / Act (행동) · 결정을 실행하고 그 결과가 다시 관찰 입력이 됨 / 루프 속도 (Tempo) · 상대보다 빠르게 순환하는 것 자체가 경쟁우위
- 단계: Observe(관찰) 단계에서 시장·경쟁·고객·내부 지표의 변화 신호를 빠짐없이 수집합니다. → Orient(판단) 단계에서 그 신호를 우리의 가정·경험·문화에 비춰 지금 무슨 일이 벌어지는지 재해석합니다. → 기존 정신 모델이 현실과 어긋나면 과감히 깨고 새 해석을 채택합니다. → Decide(결정) 단계에서 재해석을 바탕으로 가장 합리적인 행동 가설을 빠르게 선택합니다. → Act(행동) 단계에서 작게 실행하고 그 결과를 즉시 관찰 단계로 되돌립니다. → 한 바퀴를 경쟁자보다 짧은 주기로 반복해 상대의 대응을 앞지릅니다.
- 한계: 속도에만 집착하면 깊이 있는 분석이나 장기 전략을 희생할 수 있습니다. Orient 단계가 편향되면 빠른 결정이 빠른 오판이 됩니다. 안정적이고 예측 가능한 환경에서는 PDCA 같은 체계적 개선이 더 적합합니다.
- 빈도 ★★★☆☆ · 효과 ★★★★☆
- 갤러리 관련: #58 PDCA 사이클, #2 시나리오 플래닝, #10 리스크 매트릭스
- 카드: https://strategy.airoasting.com/#70

### #11. 3C 분석 (3C Analysis)
- 한 줄: 가장 범용적인 시장 구조 분석 도구입니다.
- 쓸 때: 신사업·신규 시장 진입 초기 진단; 기존 사업의 포지셔닝 재점검; 복잡한 상황을 빠르게 구조화해야 할 때; 더 깊은 분석(5 Forces, STP) 전에 큰 그림을 잡을 때
- 뼈대: Customer · 시장 규모, 성장, 세그먼트, 니즈 변화 / Competitor · 주요 경쟁자, 시장 점유, 강점·약점 / Company · 자사 자원, 역량, 포지션, 약점
- 단계: Customer를 분석합니다 (시장 정의, 규모·성장, 세그먼트, 니즈와 구매 패턴). → Competitor를 분석합니다 (직간접 경쟁자, 점유율·매출, 전략). → Company를 분석합니다 (자원, 역량, 강점·약점, 재무). → 세 축의 교차점을 분석합니다 (고객이 원하지만 경쟁사가 못 주고 자사가 줄 수 있는 영역). → KSF(핵심 성공 요인)를 도출합니다. → 전략 방향에 대한 1차 결론을 정리합니다.
- 한계: 구조를 잡기에는 좋지만 깊이 있는 분석에는 한계가 있습니다. 거시환경(PEST) 변수가 빠져 있습니다. 시간축(변화 추세) 반영이 약합니다.
- 빈도 ★★★★★ · 효과 ★★★★☆

### #12. SWOT 분석 (SWOT Analysis)
- 한 줄: 널리 쓰이지만 단독으로는 깊이가 부족한 도구입니다.
- 쓸 때: 전략 워크숍에서 빠른 합의가 필요할 때; 다른 분석(3C, 5 Forces) 결과를 종합할 때; 임원·이해관계자에게 큰 그림을 보여줘야 할 때; 단, 깊이 있는 진단의 메인 도구로는 부적절합니다
- 뼈대: S · 내부 강점 / W · 내부 약점 / O · 외부 기회 / T · 외부 위협 / SO·WO·ST·WT · 4가지 교차 전략
- 단계: 내부 분석으로 S와 W를 도출합니다 (자원, 역량, 재무, 브랜드). → 외부 분석으로 O와 T를 도출합니다 (시장, 경쟁, 규제, 기술). → 단순 나열로 끝내지 말고 다음 단계로 갑니다. → SO 전략을 만듭니다 (강점으로 기회를 잡는 공격 전략). → WO 전략을 만듭니다 (약점을 보완해 기회를 잡는 보완 전략). → ST 전략을 만듭니다 (강점으로 위협을 무력화). → WT 전략을 만듭니다 (최악 시나리오 방어).
- 한계: 내부와 외부 구분이 모호한 항목이 많습니다. 우선순위와 가중치가 빠져 있어 모든 항목이 동등해 보입니다. 정태적이라 시장 변화 속도를 반영하기 어렵습니다. 단독으로는 깊이가 부족하므로 3C, 5 Forces, PEST와 결합해야 합니다.
- 빈도 ★★★★★ · 효과 ★★☆☆☆
- 갤러리 관련: #11 3C 분석, #13 5 Forces 분석, #16 PEST(EL) 분석
- 카드: https://strategy.airoasting.com/#12

### #13. 5 Forces 분석 (Porter's Five Forces)
- 한 줄: 산업 진입 전략과 구조 분석에 강력한 도구입니다.
- 쓸 때: 신규 산업 진입 의사결정; 기존 산업의 장기 매력도 재평가; 특정 산업의 수익성이 낮거나 높은 구조적 이유 분석; M&A 대상 산업 평가
- 뼈대: 1. 신규 진입자의 위협 (Threat of New Entrants) / 2. 공급자의 협상력 (Bargaining Power of Suppliers) / 3. 구매자의 협상력 (Bargaining Power of Buyers) / 4. 대체재의 위협 (Threat of Substitutes) / 5. 기존 경쟁자 간 경쟁 강도 (Competitive Rivalry)
- 단계: 분석 대상 산업과 시장 범위를 정의합니다. → 5개 힘 각각에 대해 결정 요인을 분석합니다. → 각 힘의 강도를 평가합니다 (高·中·低). → 종합 산업 매력도를 판정합니다. → 우리 사업의 포지션을 평가합니다 (어느 힘에 약한가). → 약한 힘을 강화하거나 회피하는 전략을 도출합니다.
- 한계: 정태적 분석이라 산업 변화 속도가 빠르면 한계가 있습니다. 상호 보완(파트너) 관계가 분석에서 빠집니다. 산업 정의가 모호하면 결과가 흔들립니다 (예: 어디까지가 '미디어 산업'인가). 디지털 플랫폼·생태계 비즈니스에는 추가 도구(BMC, 가치 사슬)가 필요합니다.
- 빈도 ★★★★☆ · 효과 ★★★★★
- 갤러리 관련: #11 3C 분석, #16 PEST(EL) 분석, #35 가치 사슬 분석
- 카드: https://strategy.airoasting.com/#13

### #14. BCG 성장-점유율 매트릭스 (BCG Growth-Share Matrix)
- 한 줄: 포트폴리오 자원 배분의 가장 널리 쓰이는 도구입니다.
- 쓸 때: 다사업 포트폴리오 자원 배분 결정; 어느 사업에 투자하고 어느 사업을 철수할지 판단; 사업 단위별 전략 우선순위 설정; M&A 이후 포트폴리오 재편 검토
- 뼈대: Star (스타) · 고성장·고점유 → 투자 유지 / Cash Cow (현금소) · 저성장·고점유 → 수확·현금 창출 / Question Mark (물음표) · 고성장·저점유 → 선택적 투자 또는 철수 / Dog (개) · 저성장·저점유 → 철수 또는 유지 최소화
- 단계: 포트폴리오 내 사업 단위를 정의합니다. → 각 사업의 시장 성장률을 산출합니다 (보통 10%가 고/저 기준). → 각 사업의 상대적 시장 점유율(자사/1위 경쟁사)을 산출합니다 (1.0 기준). → 버블 크기를 매출 또는 이익으로 설정합니다. → 매트릭스에 각 사업을 위치시킵니다. → 스타→현금소→물음표 순으로 자원 배분 방향을 결정합니다. → 개는 원가 절감 또는 철수를 검토합니다.
- 한계: 시장 성장률·점유율만으로 사업 매력도가 모두 설명되지 않습니다. 시장 정의에 따라 위치가 크게 달라집니다. 정태적 스냅숏이므로 동태적 시장 변화를 반영하지 못합니다. 보다 정교한 분석에는 GE-McKinsey 9Box를 써야 합니다.
- 빈도 ★★★★★ · 효과 ★★★★☆

### #15. Ansoff 성장 매트릭스 (Ansoff Growth Matrix)
- 한 줄: 성장 방향 결정의 첫 번째 도구입니다.
- 쓸 때: 성장 전략 방향을 결정해야 할 때; 어느 성장 옵션에 자원을 배분할지 토론할 때; 신사업 진출 위험을 평가할 때; 전략 워크숍에서 성장 경로를 합의할 때
- 뼈대: 시장 침투 (Market Penetration) · 기존 제품 × 기존 시장 → 위험 最低 / 제품 개발 (Product Development) · 신제품 × 기존 시장 → 위험 中 / 시장 개발 (Market Development) · 기존 제품 × 신규 시장 → 위험 中 / 다각화 (Diversification) · 신제품 × 신규 시장 → 위험 最高
- 단계: 현재 사업의 제품과 시장을 정의합니다. → 4개 사분면의 옵션을 구체화합니다. → 각 옵션의 시장 규모, 성장성, 위험을 평가합니다. → 자사 역량(자원, 역량, 재무)과의 적합도를 검토합니다. → 1~2개 우선 성장 경로를 선택합니다. → 선택한 경로의 실행 계획을 수립합니다.
- 한계: 4개 옵션이 상호 배타적이지 않아 동시에 추진하는 경우도 많습니다. 각 옵션의 실행 가능성이나 경쟁 환경은 별도 분석이 필요합니다. 위험 수준은 단순화이며 실제는 맥락에 따라 크게 다릅니다.
- 빈도 ★★★★★ · 효과 ★★★★☆

### #24. Jobs-to-be-Done (JTBD 프레임워크)

- 쓸 때: 기존 제품의 혁신 방향을 찾을 때; 고객 조사로 표면적 요구 너머의 니즈를 발굴할 때; 신제품 아이디어의 타당성을 검증할 때; 경쟁사와 다른 차원의 차별화를 설계할 때
- 뼈대: 기능적 Job · 실용적으로 해결해야 할 과제 ("A에서 B로 이동") / 감성적 Job · 그 과정에서 느끼고 싶은 감정 ("안전하다는 느낌") / 사회적 Job · 타인에게 어떻게 보이고 싶은가 ("성공한 사람처럼") / 고용·해고 구조 · 언제 어떤 제품을 고용하고 왜 해고하는가
- 단계: 관찰과 인터뷰로 고객의 행동 맥락을 수집합니다. → 각 행동에서 "왜 그 제품/서비스를 선택했는가?"를 파고듭니다. → 기능적·감성적·사회적 Job을 각각 정의합니다. → 현재 제품이 얼마나 잘 그 Job을 수행하는지 평가합니다. → Job이 제대로 충족되지 않는 영역(언더서브드)을 찾습니다. → 새로운 제품·서비스 아이디어를 Job 관점으로 평가합니다.
- 한계: Job 정의가 너무 넓으면 모든 제품이 경쟁자가 됩니다. 정성 조사 중심이라 규모 있는 데이터와 결합해야 합니다. 발견한 Job을 실제 제품으로 구현하는 것은 또 다른 과제입니다.
- 빈도 ★★★☆☆ · 효과 ★★★★★

### #25. Kano 모델 (Kano Model)
- 한 줄: 제품 기능의 우선순위를 고객 만족 관점에서 설계하는 도구입니다.
- 쓸 때: 신제품·신기능의 개발 우선순위를 설정할 때; 고객이 실제로 중요하게 여기는 기능을 파악할 때; 제한된 개발 자원을 어디에 쓸지 결정할 때; 경쟁사 대비 차별화 기능을 찾을 때
- 뼈대: 기본 기능 (Must-be / Basic) · 없으면 불만이지만 있어도 당연하게 여김 (예: 호텔 객실의 온수) / 성능 기능 (Performance / Linear) · 더 좋을수록 만족도가 오름 (예: 배터리 용량) / 매력 기능 (Attractive / Delighter) · 예상 못 했지만 있으면 크게 기쁨 (예: 무선 충전 초기) / 무관심 기능 (Indifferent) · 있어도 없어도 만족에 영향 없음 / 역기능 (Reverse) · 있으면 오히려 불만
- 단계: 평가할 기능 목록을 작성합니다. → 설문 설계: 각 기능에 대해 "있으면?" / "없으면?"을 쌍으로 묻습니다. → 5점 척도로 응답을 수집합니다 (매우 좋다~매우 싫다). → Kano 평가표로 각 기능을 분류합니다. → 기본 기능을 먼저 확인해 결함이 없는지 점검합니다. → 성능 기능 중 투자 대비 효과가 큰 것을 선택합니다. → 매력 기능을 차별화 카드로 활용합니다.
- 한계: 설문 설계가 까다롭고 응답자 해석 차이가 생깁니다. 기능 분류는 시간이 지나면서 이동합니다 (매력→성능→기본). 분류만으로는 실제 개발 우선순위가 결정되지 않아 투자 비용 분석이 필요합니다.
- 빈도 ★★☆☆☆ · 효과 ★★★★☆
- 갤러리 관련: #24 Jobs-to-be-Done, #23 Customer Journey Map, #22 4P (마케팅 믹스)
- 카드: https://strategy.airoasting.com/#25

### #26. 포지셔닝 맵 (Perceptual Map / Competitive Positioning Map)
- 한 줄: 두 축으로 경쟁 제품의 인식 위치를 시각화해 빈 포지션 기회를 발견하는 도구입니다.
- 쓸 때: 신제품 포지셔닝 전략을 수립할 때; 경쟁 구도를 한눈에 이해해야 할 때; 기존 제품의 리포지셔닝(방향 전환)을 검토할 때; STP의 Positioning 단계를 시각화할 때
- 뼈대: X·Y 축 · 고객이 중요하게 생각하는 두 가지 핵심 속성 / 경쟁사 플롯 · 각 경쟁사·제품을 좌표에 배치 / 자사 플롯 · 현재 위치 및 목표 위치 / 화이트 스페이스 · 경쟁이 없는 매력적 포지션 / 지각도 데이터 · 고객 설문·브랜드 인식 조사로 검증
- 단계: 고객이 구매 시 가장 중요하게 보는 속성 2가지를 선택합니다 (설문 또는 인터뷰). → X축·Y축에 속성과 방향(낮음↔높음)을 설정합니다. → 주요 경쟁사를 각 축 기준으로 좌표에 배치합니다. → 자사의 현재 위치를 표시합니다. → 군집(cluster)과 공백(white space)을 찾습니다. → 목표 포지션을 정하고 그곳으로 이동하기 위한 전략을 수립합니다.
- 한계: 두 축만으로는 복잡한 경쟁 구도를 단순화할 수 있습니다. 축 선택이 잘못되면 맵의 유용성이 크게 떨어집니다. 고객 인식 데이터 없이 내부 직관만으로 작성하면 왜곡됩니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆

### #27. AARRR 퍼널 분석 (AARRR Funnel (Pirate Metrics))
- 한 줄: 스타트업 성장을 다섯 단계 깔때기로 측정하는 도구입니다.
- 쓸 때: 스타트업 성장의 병목 단계를 찾을 때; 제품 깔때기를 단계별 지표로 관리할 때; 한정된 자원으로 개선 우선순위를 정할 때; 그로스 실험의 효과를 측정할 때
- 뼈대: 획득 (Acquisition) / 활성화 (Activation) / 유지 (Retention) / 수익 (Revenue) / 추천 (Referral)
- 단계: 제품의 사용자 여정을 다섯 단계로 정의합니다. → 각 단계의 핵심 지표를 선정합니다. → 단계별 전환율과 이탈률을 측정합니다. → 가장 크게 새는 병목 단계를 찾습니다. → 병목 단계 개선 실험을 설계합니다. → 실험 결과를 지표 변화로 검증합니다. → 우선순위를 갱신하며 반복합니다.
- 한계: 단계를 선형으로 봐 실제 비선형 여정을 단순화합니다. 지표에만 집중하다 제품 본질을 놓칠 수 있습니다. 비즈니스 모델에 따라 단계 정의가 달라져야 합니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆
- 갤러리 관련: #23 Customer Journey Map, #28 RFM 분석, #39 OKR
- 카드: https://strategy.airoasting.com/#27

### #28. RFM 분석 (RFM Analysis)
- 한 줄: 구매 행동으로 고객을 등급화하는 도구입니다.
- 쓸 때: 거래 데이터로 고객을 세분화할 때; 우량 고객과 이탈 위험 고객을 구분할 때; 마케팅 예산을 고객 등급별로 배분할 때; 재구매와 이탈 방지 캠페인을 설계할 때
- 뼈대: 최근성 (Recency) / 빈도 (Frequency) / 금액 (Monetary) / 점수 등급 (Scoring) / 고객 세그먼트
- 단계: 고객별 거래 데이터를 수집합니다. → 최근 구매 시점을 측정합니다. → 일정 기간 구매 빈도를 집계합니다. → 누적 구매 금액을 계산합니다. → 세 지표를 각각 점수로 등급화합니다. → 점수 조합으로 고객 세그먼트를 만듭니다. → 세그먼트별 차별화된 마케팅을 실행합니다.
- 한계: 과거 구매 행동만 보고 미래 잠재력은 반영하지 못합니다. 신규 고객은 데이터가 적어 평가가 어렵습니다. 구매 이유나 만족도 같은 정성 정보가 빠집니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆

### #29. AIDA 모델 (AIDA Funnel)
- 한 줄: 고객을 인지에서 행동까지 이끄는 설득 단계 도구입니다.
- 쓸 때: 광고나 세일즈 메시지를 단계별로 설계할 때; 구매 전환 깔때기의 약한 단계를 진단할 때; 랜딩페이지나 카피의 흐름을 구성할 때; 캠페인의 소비자 심리 흐름을 점검할 때
- 뼈대: 주목 (Attention) / 흥미 (Interest) / 욕구 (Desire) / 행동 (Action) / 단계별 전환
- 단계: 목표 고객과 메시지 목적을 정의합니다. → 주목 단계에서 시선을 끄는 후크를 만듭니다. → 흥미 단계에서 관련성과 혜택을 전달합니다. → 욕구 단계에서 구매 욕구를 자극합니다. → 행동 단계에서 명확한 행동 유도(CTA)를 제시합니다. → 단계별 전환을 측정합니다. → 약한 단계의 메시지를 개선합니다.
- 한계: 선형 단계 가정이 실제 비선형 구매 여정과 다릅니다. 구매 후 충성도와 재구매를 다루지 않습니다. 디지털 환경의 복잡한 접점을 단순화합니다.
- 빈도 ★★★★☆ · 효과 ★★★☆☆

### #30. 비즈니스 모델 캔버스 (Business Model Canvas)
- 한 줄: 사업 모델을 9개 블록으로 한 장에 시각화하는 표준 도구입니다.
- 쓸 때: 신규 사업·서비스의 초기 모델링 단계; 기존 사업을 한 장으로 외부에 설명해야 할 때; 팀원이 사업 구성요소에 대해 같은 그림을 공유해야 할 때; 피벗·리뉴얼 직전, 현재 모델을 빠르게 진단할 때
- 뼈대: Customer Segments (고객 세그먼트) / Value Propositions (가치 제안) / Channels (채널) / Customer Relationships (고객 관계) / Revenue Streams (수익원) / Key Resources (핵심 자원) / Key Activities (핵심 활동) / Key Partnerships (핵심 파트너) / Cost Structure (비용 구조)
- 단계: 고객 세그먼트를 먼저 정의합니다 (누구의 어떤 문제를 푸는가). → 가치 제안을 작성합니다 (고객이 우리를 선택해야 하는 이유). → 채널과 고객 관계를 설계합니다 (어떻게 닿고 어떻게 유지하는가). → 수익원을 정의합니다 (어떤 형태로 돈을 받는가). → 핵심 자원·활동·파트너를 정리합니다 (가치 제공을 가능하게 하는 뒷단). → 비용 구조를 점검합니다 (가장 큰 비용은 무엇인가). → 9블록이 한 방향을 가리키는지 일관성을 점검합니다.
- 한계: 각 블록이 한 장에 압축되어 있어 깊이 있는 분석은 어렵습니다. 경쟁·환경 분석이 약하므로 5 Forces나 PEST와 함께 써야 합니다. 캔버스를 채우는 것 자체에 만족하기 쉬우므로, 실제 가설 검증이 더 중요합니다.

### #31. 이익 방정식 (Profit Equation)
- 한 줄: 수익성 개선을 위한 전략적 구조 이해에 가장 강한 도구입니다.
- 쓸 때: 이익이 떨어진 사업의 원인을 정량으로 진단할 때; 가격 인상이나 할인 의사결정의 영향을 시뮬레이션할 때; 원가 절감과 매출 증대 중 어느 쪽이 더 효과적인지 우선순위를 정할 때; 여러 사업 단위의 수익성을 비교 분석할 때
- 뼈대: P (가격, Price) / V (단위 변동비, Variable Cost) / Q (판매 수량, Quantity) / F (고정비, Fixed Cost) / 공헌이익 (P − V)
- 단계: 현재 P, V, Q, F 수치를 확보합니다. → 단위 공헌이익(P−V)과 손익분기점을 계산합니다. → 각 변수가 1% 변할 때 이익이 얼마나 변하는지 민감도를 산정합니다. → 가장 큰 이익 레버를 식별합니다. → 실행 옵션을 도출합니다 (가격 인상, 믹스 변경, 원가 절감, 고정비 구조조정 등). → 시나리오별로 이익 변화를 시뮬레이션합니다.
- 한계: 장기적·전략적 효과(브랜드, 고객 충성도)는 반영하기 어렵습니다. 수요 탄력성 같은 변수의 추정이 부정확하면 결과가 왜곡됩니다. 다품종 사업에서는 변수를 단순화하기가 까다롭습니다.
- 빈도 ★★★★★ · 효과 ★★★★★
- 갤러리 관련: #30 비즈니스 모델 캔버스, #32 비즈니스 모델 (수익 모델), #52 프로세스 분해

### #32. 비즈니스 모델 (수익 모델) (Revenue Model)
- 한 줄: 플랫폼·디지털 사업의 수익 구조를 설계하는 데 적합한 도구입니다.
- 쓸 때: 신규 디지털·플랫폼 사업의 수익화 방식을 결정할 때; 기존 사업의 수익화 방식을 다각화할 때; 프리·유료 전환(프리미엄)을 설계할 때; 양면 시장의 가격 구조를 설계할 때
- 뼈대: 수익원 유형 (구독·거래·광고·라이선스·프리미엄·판매) / Payer (누가 지불하는가) / Pricing 단위 (사용자당, 거래당, 정액) / 결제 주기 (월·연·일회성) / 수익화 시점 (가입·사용·전환)
- 단계: 우리가 만드는 가치를 명세화합니다. → 가치를 가장 강하게 느끼는 주체를 식별합니다 (payer 후보). → 수익원 유형 후보를 3~5가지 도출합니다. → 각 유형의 단가, 전환율, LTV를 추정합니다. → CAC와 비교해 단위경제성을 검증합니다. → 1차 모델을 결정하고, 2차 확장 모델 시나리오까지 그립니다.
- 한계: 혼자 쓰면 시장·경쟁 관점이 빠지기 쉬우므로 BMC와 함께 쓰는 것이 좋습니다. 초기 가설은 빠르게 검증해야 합니다. 책상 위 설계만으로는 한계가 큽니다. B2B 복잡 거래는 단순 패턴으로 환원되지 않습니다.

### #33. Lean Canvas (린 캔버스)

- 한계: BMC보다 단순화되어 있어 복잡한 사업 모델엔 부족합니다. 가설 검증을 실제로 실행하지 않으면 서류에 그칩니다. 성장 단계의 기업에는 BMC나 OKR이 더 적합할 수 있습니다.

### #68. 유닛 이코노믹스 (Unit Economics (LTV · CAC))
- 한 줄: 고객 한 명 단위로 사업의 수익성을 검증하는 구독·디지털 사업의 표준 도구입니다.
- 쓸 때: 구독·SaaS·이커머스 등 고객을 반복 확보하는 사업의 수익성 진단; 마케팅비를 더 써서 성장할지, 효율을 높일지 판단할 때; 투자 유치 단계에서 사업의 단위 수익성을 증명해야 할 때; 여러 채널·세그먼트 중 어디에 획득 예산을 배분할지 정할 때
- 뼈대: LTV (고객생애가치) · ARPU × 매출총이익률 × 평균 고객수명(또는 ÷ 이탈률) / CAC (고객획득비용) · 획득 마케팅·영업비 ÷ 신규 고객 수 / LTV/CAC 비율 · 3 이상 건강, 1~3 개선 필요, 1 미만 적자 구조 / CAC 회수기간 (Payback) · CAC를 월 공헌이익으로 나눈 회수 개월 수 / 이탈률·유지율 (Churn / Retention) · LTV를 결정하는 핵심 변수
- 단계: 분석 단위(고객 1명 또는 거래 1건)를 정의합니다. → ARPU, 매출총이익률, 평균 고객수명(또는 이탈률)으로 LTV를 계산합니다. → 일정 기간의 획득 비용 총액을 신규 고객 수로 나눠 CAC를 계산합니다. → LTV ÷ CAC 비율과 CAC 회수기간을 산출합니다. → 비율이 3 미만이거나 회수기간이 너무 길면 원인을 분해합니다 (이탈↑? 단가↓? 획득비↑?). → 가장 효과적인 레버(유지율 개선, 단가 인상, 채널 효율화)부터 개선합니다. → 채널·세그먼트별로 쪼개 다시 계산해 예산을 재배분합니다.
- 한계: 초기 데이터가 적으면 이탈률·수명 추정이 부정확해 LTV가 크게 흔들립니다. 평균값에 의존하면 우량·불량 고객이 섞여 실제 구조를 가립니다. 세그먼트별로 봐야 합니다. 단위 수익성이 좋아도 시장 규모(TAM)가 작으면 사업이 커지지 못합니다.
- 빈도 ★★★★☆ · 효과 ★★★★★
- 갤러리 관련: #31 이익 방정식, #32 비즈니스 모델 (수익 모델), #27 AARRR 퍼널 분석

### #69. 밸류 스틱 (Value Stick (WTP–WTS, Value-Based Strategy))
- 한 줄: 지불의향가격과 판매의향가격 사이의 가치 창출을 막대 하나로 보는 가치 기반 전략 도구입니다.
- 쓸 때: 가격 경쟁에서 벗어나 가치 창출 관점으로 전략을 재구성할 때; 제품 차별화로 고객의 지불의향(WTP)을 올릴 여지를 찾을 때; 공급망·직원 측면에서 판매의향(WTS)을 낮춰 비용 우위를 만들 때; 경영진에게 '왜 이 전략이 가치를 키우는가'를 한 장으로 설명할 때
- 뼈대: WTP (지불의향가격) · 고객이 낼 수 있는 최대 금액. 막대의 천장 / Price (가격) · 실제 판매 가격 / Cost (비용) · 제품·서비스를 만드는 비용 / WTS (판매의향가격) · 공급자·직원이 받아들이는 최소 보상. 막대의 바닥 / 고객 기쁨 (WTP−Price) · 고객이 가져가는 잉여 / 기업 마진 (Price−Cost) · 기업이 가져가는 몫 / 공급자 잉여 (Cost−WTS) · 공급자·직원이 가져가는 몫
- 단계: 대상 제품·고객을 정하고 세로 막대에 WTP·가격·비용·WTS 네 점을 표시합니다. → 전체 길이(WTP−WTS)로 현재 창출 중인 총가치를 가늠합니다. → 세 몫(고객 기쁨·기업 마진·공급자 잉여)이 어떻게 나뉘는지 봅니다. → WTP를 올릴 레버를 찾습니다 (품질·브랜드·보완재·네트워크 효과). → WTS를 낮출 레버를 찾습니다 (직원 만족·공급자 협업·일하기 좋은 조건). → 가격을 직접 깎지 않고도 고객 기쁨과 기업 마진을 동시에 키우는 길을 설계합니다. → 경쟁사 대비 막대 길이와 분배 구조를 비교해 차별화 포인트를 정합니다.
- 한계: WTP와 WTS는 직접 관측이 어려워 설문·실험으로 추정해야 합니다. 개념적 통찰은 강하지만, 구체적 실행은 별도의 마케팅·운영 분석이 필요합니다. 세그먼트마다 WTP가 달라 단일 막대로 단순화하면 현실을 놓칠 수 있습니다.
- 빈도 ★★★☆☆ · 효과 ★★★★☆

### #37. 맥킨지 7S 분석 (McKinsey 7S Framework)
- 한 줄: 조직 정렬성과 전략 실행 진단에 유용한 도구입니다.

### #39. OKR (Objectives and Key Results)
- 한 줄: 전략 목표를 분기 단위 실행으로 연결하는 목표 관리 도구입니다.
- 쓸 때: 전략 목표를 분기·반기 실행으로 연결할 때; 팀 간 목표 정렬이 필요할 때; 빠른 환경 변화에 적응적으로 목표를 조정해야 할 때; KPI 체계는 있지만 실행 동력이 부족할 때
- 뼈대: Objective (O) · 명확하고 도전적인 질적 목표. "무엇을 달성할 것인가" / Key Results (KR) · 목표 달성 여부를 측정하는 정량 지표 (보통 3~5개) / 정렬 (Alignment) · 전사 O → 팀 O → 개인 O의 수직 연결 / 주기 · 보통 분기별 설정·리뷰 / 채점 (Scoring) · 0~1.0, 0.7이 이상적 달성 수준
- 단계: 전사 전략 방향을 기반으로 O를 설정합니다 (3~5개). → 각 O에 KR을 3~5개씩 정합니다. KR은 숫자로 측정 가능해야 합니다. → 팀·개인 OKR을 전사 OKR과 연결합니다. → 주간 체크인으로 진행 상황을 모니터링합니다. → 분기 말에 0~1.0로 채점하고 다음 OKR을 설계합니다. → 0.7 미만은 개선, 1.0은 목표가 너무 쉬웠는지 재검토합니다.
- 한계: OKR 설정이 어렵고, 잘못 설계하면 기존 KPI 관리와 다를 바 없습니다. 성과 평가와 연동하면 도전적 목표 설정을 기피하게 됩니다. 도입 초기 조직 문화 변화 없이는 형식에 그치기 쉽습니다.

### #40. VRIO 분석 (VRIO Framework)

- 단계: 분석할 자원과 역량 목록을 작성합니다. → 그 자원이 기회를 살리거나 위협을 막는 가치가 있는지 봅니다. → 경쟁자 대비 희소한지 평가합니다. → 모방하거나 대체하기 어려운지 판단합니다. → 조직이 그 자원을 활용할 체계를 갖췄는지 확인합니다. → 네 기준 결과로 경쟁우위 수준을 판정합니다. → 지속적 우위 자원에 투자를 집중합니다.

### #45. 역량 모델 (Competency Model)
- 한 줄: 직무 성공에 필요한 지식·기술·태도를 구조화해 채용·평가·육성의 기준으로 삼는 도구입니다.

- 한계: 역량 사전 구축에 많은 시간과 비용이 듭니다. 한번 만들면 환경 변화에도 갱신되지 않고 형식화되기 쉽습니다. 행동 지표가 추상적이면 평가자마다 해석이 달라집니다.

### #46. Tuckman 팀 발달 5단계 (Tuckman's Stages of Group Development)
- 한 줄: 팀이 형성부터 해체까지 거치는 5단계를 통해 팀 상태를 진단하는 모델입니다.
- 쓸 때: 새로 구성된 팀의 현재 상태를 진단할 때; 팀 내 갈등이 정상 과정인지 판단할 때; 단계에 맞는 리더십 스타일을 정할 때; 프로젝트 팀의 협업 흐름을 설계할 때
- 뼈대: 형성기 (Forming) · 서로 탐색하며 의존하는 시기 / 격동기 (Storming) · 갈등과 주도권 다툼이 표출되는 시기 / 규범기 (Norming) · 규칙과 신뢰가 자리잡는 시기 / 성과기 (Performing) · 자율적으로 성과를 내는 시기 / 해산기 (Adjourning) · 목표 달성 후 팀을 마무리하는 시기
- 단계: 팀이 현재 어느 단계에 있는지 행동 신호로 진단합니다. → 형성기에는 목표와 역할을 명확히 제시합니다. → 격동기의 갈등을 억누르지 않고 표면화해 조율합니다. → 규범기에는 합의된 규칙과 협업 방식을 정착시킵니다. → 성과기에는 권한을 위임하고 자율성을 부여합니다. → 해산기에는 성과를 평가하고 학습을 정리합니다. → 구성원 변동 시 단계가 후퇴할 수 있음을 관리합니다.
- 한계: 모든 팀이 단계를 순서대로 밟지는 않습니다. 단계 구분이 모호해 현재 위치 판단이 주관적입니다. 단계를 안다고 해서 구체적 개입 방법까지 알려주지는 않습니다.
- 빈도 ★★★★☆ · 효과 ★★★☆☆

### #47. 허즈버그 2요인 이론 (Herzberg Two-Factor Theory)
- 한 줄: 직무 만족과 불만족을 서로 다른 두 요인으로 나눠 동기 부여를 설계하는 이론입니다.
- 쓸 때: 보상을 올려도 몰입이 오르지 않는 원인을 진단할 때; 직무 설계로 내재 동기를 높이려 할 때; 직원 만족도 조사 결과를 해석할 때; 제한된 예산에서 동기 부여 우선순위를 정할 때
- 뼈대: 동기 요인 (Motivators) · 만족을 높이는 요인 / 성취 (Achievement) · 일의 완수와 결과 / 인정 (Recognition) · 기여에 대한 인정 / 일 자체 (Work Itself) · 직무의 의미와 도전 / 위생 요인 (Hygiene Factors) · 불만족을 막는 요인 / 급여·근무 조건 (Pay, Conditions) · 보상과 환경 / 회사 정책·관계 (Policy, Relations) · 제도와 대인 관계
- 단계: 현재 직원의 불만족 요인과 만족 요인을 분리해 조사합니다. → 위생 요인의 결핍 여부를 먼저 점검합니다. → 위생 요인을 최소 기준 이상으로 충족시킵니다. → 만족을 높일 동기 요인을 식별합니다. → 직무 충실화로 성취·책임·성장 기회를 설계합니다. → 인정과 피드백 체계를 도입합니다. → 두 요인의 개선 효과를 분리해 측정합니다.
- 한계: 1950년대 특정 직군 연구라 일반화에 한계가 있습니다. 같은 요인이 사람에 따라 동기와 위생을 오갑니다. 만족과 성과의 인과를 직접 입증하지는 못합니다.

### #48. 커크패트릭 4단계 교육평가 (Kirkpatrick Four-Level Evaluation)

- 쓸 때: 교육 프로그램의 효과를 체계적으로 측정할 때; 교육 투자(ROI)의 근거를 경영진에 제시할 때; 현재 교육 평가가 만족도에만 머무는지 점검할 때; 교육 설계 단계에서 평가 지표를 미리 정할 때
- 뼈대: 1단계 반응 (Reaction) · 교육에 대한 만족도 / 2단계 학습 (Learning) · 지식·기술의 습득 정도 / 3단계 행동 (Behavior) · 현업에서의 적용 / 4단계 결과 (Results) · 경영 성과 기여 / 평가 시점 (Timing) · 단계별 측정 시기 / 평가 방법 (Method) · 설문·시험·관찰·지표
- 단계: 교육 목표와 기대 성과를 먼저 정의합니다. → 4단계 중 어디까지 측정할지 범위를 정합니다. → 결과(4단계)에서 역산해 평가 지표를 설계합니다. → 교육 직후 반응과 학습을 측정합니다. → 일정 기간 후 현업 행동 변화를 관찰합니다. → 경영 지표로 결과 기여를 분석합니다. → 결과를 다음 교육 설계에 환류합니다.
- 한계: 3·4단계 측정에 시간과 비용이 많이 듭니다. 교육 외 변수와 성과의 인과를 분리하기 어렵습니다. 실무에서는 대부분 1·2단계에서 멈춥니다.

### #50. GROW 코칭 모델 (GROW Coaching Model)
- 한 줄: 목표·현실·대안·실행의지 네 단계로 코칭 대화를 구조화하는 모델입니다.
- 쓸 때: 관리자가 부하 직원과 1대1 코칭을 할 때; 목표 설정과 실행 계획 면담을 구조화할 때; 답을 주기보다 스스로 답을 찾게 돕고 싶을 때; 성과 면담을 일관된 흐름으로 진행할 때
- 뼈대: Goal (목표) · 대화에서 도달하려는 지점 / Reality (현실) · 현재 상황과 사실 점검 / Options (대안) · 가능한 선택지 탐색 / Will (실행 의지) · 구체적 행동과 약속 / 질문 (Questions) · 답을 끌어내는 개방형 질문 / 경청 (Listening) · 판단 없이 듣는 태도
- 단계: 이번 대화의 구체적 목표를 함께 정합니다. → 현재 상황과 사실을 질문으로 점검합니다. → 목표와 현실의 격차를 명확히 합니다. → 가능한 대안을 넓게 탐색합니다. → 대안의 장단점을 함께 검토합니다. → 실행할 행동과 시점을 본인이 정하게 합니다. → 실행 의지와 후속 점검 방식을 약속합니다.
- 한계: 코치의 질문 역량에 따라 효과 편차가 큽니다. 즉각적 답이 필요한 위기 상황에는 맞지 않습니다. 구조에 갇히면 대화가 형식적으로 흐를 수 있습니다.

### #51. 매슬로 욕구단계 (Maslow Hierarchy of Needs)

- 뼈대: 생리적 욕구 (Physiological) / 안전 욕구 (Safety) / 사회적 욕구 (Belonging) / 존중 욕구 (Esteem) / 자아실현 욕구 (Self-actualization) / 결핍 욕구와 성장 욕구 구분
- 단계: 구성원이 현재 어느 단계의 욕구에 머물러 있는지 진단합니다. → 생리·안전 등 하위 욕구의 충족 여부를 먼저 확인합니다. → 미충족된 가장 낮은 단계를 우선 해결 대상으로 정합니다. → 사회적·존중 욕구에 해당하는 제도와 문화를 점검합니다. → 단계별로 맞는 동기 부여 수단을 매칭합니다. → 자아실현 단계의 성장 기회를 상위 인재에게 제공합니다. → 욕구 충족 상태의 변화를 주기적으로 재진단합니다.
- 한계: 욕구가 단계대로 순차 충족된다는 가정이 실증적으로 약합니다. 문화와 개인에 따라 욕구의 우선순위가 달라집니다. 동기를 진단하는 틀일 뿐 구체적 실행 방안은 제시하지 못합니다.

### #52. 프로세스 분해 (Process Decomposition)
- 한 줄: 서비스 흐름과 업무 병목을 구조화하는 기본 도구입니다.

- 뼈대: 단계(Activity) · 처리 활동 / 투입(Input) · 사람, 시스템, 정보 / 산출(Output) · 다음 단계로의 전달물 / 처리 시간 / 대기 시간 / 이슈 / 페인포인트 / KPI
- 단계: 분석 대상 프로세스의 시작과 끝을 정의합니다. → 단계별로 활동을 분해합니다 (5~15단계). → 단계별 처리 시간과 대기 시간을 측정합니다. → 각 단계의 입력·출력·담당을 명세합니다. → 전체 흐름도를 시각화합니다 (스윔레인 등). → 병목·중복·대기를 식별합니다. → 자동화·통합·삭제 대상을 도출합니다.
- 한계: 현재 프로세스를 그대로 옮기면 디지털화해도 비효율이 그대로 남습니다. 프로세스 외부의 시스템·조직 이슈가 빠지기 쉽습니다. 업무가 비정형(지식 노동)일수록 분해 효과가 떨어집니다.

### #53. RACI 차트 (RACI Matrix)
- 한 줄: 업무 단계마다 누가 어떤 책임을 지는지 명확히 구분하는 도구입니다.
- 쓸 때: 여러 부서·팀이 얽힌 프로젝트; 신규 프로세스 도입 시 책임 분장; 의사결정이 자주 막히는 영역; 조직 개편·업무 이관
- 뼈대: R · Responsible (실제로 일을 하는 사람, 여러 명 가능) / A · Accountable (최종 책임자, 반드시 1명) / C · Consulted (의견을 듣는 양방향 소통) / I · Informed (결과를 통보받는 일방 소통) / 활동(행) × 역할/사람(열) 매트릭스
- 단계: 분석 대상 활동·의사결정을 행으로 나열합니다. → 관련된 역할·사람을 열로 나열합니다. → 각 셀에 R/A/C/I를 표기합니다. → 룰을 점검합니다: 모든 행에 A가 정확히 1명 있는지. → 룰을 점검합니다: R이 너무 많지 않은지 (병목 위험). → 룰을 점검합니다: A와 R이 같은 사람일 수 있으나 명시가 필요한지. → 이해관계자 합의 후 실행에 들어갑니다.
- 한계: A 책임자가 흐릿하면 매트릭스가 무력화됩니다. 너무 세밀하면 작성과 유지 비용이 큽니다. 조직 문화가 책임 분장에 보수적이면 표면적 합의에 그치기 쉽습니다.
- 빈도 ★★★★☆ · 효과 ★★★★★
- 갤러리 관련: #37 맥킨지 7S 분석, #52 프로세스 분해, #54 SIPOC 분석
- 카드: https://strategy.airoasting.com/#53

### #54. SIPOC 분석 (SIPOC (Supplier, Input, Process, Output, Customer))
- 한 줄: 프로세스 흐름과 이해관계자 구조를 한눈에 보여주는 도식입니다.
- 쓸 때: 프로세스 개선 프로젝트 첫 단계 (Define); 범위·이해관계자 정렬; 부서 간 책임이 모호한 프로세스 정리; 복잡한 프로세스의 큰 그림 합의
- 뼈대: Supplier · 입력을 제공하는 주체 / Input · 프로세스에 들어가는 것 (정보·자원·문서) / Process · 핵심 단계 (보통 5~7단계) / Output · 프로세스가 만들어내는 것 / Customer · 출력을 받는 주체
- 단계: Process부터 정의합니다 (5~7개 핵심 단계). → Output을 정합니다 (무엇이 만들어지는가). → Customer를 정합니다 (누가 그 출력을 쓰는가). → Input을 정합니다 (무엇이 필요한가). → Supplier를 정합니다 (누가 그 입력을 제공하는가). → 한 장에 시각화하여 이해관계자 합의를 끌어냅니다. → 다음 단계로 상세 프로세스 분해에 들어갑니다.
- 한계: 큰 그림 도구이므로 깊이는 프로세스 분해나 VSM이 보강해야 합니다. 단계 정의의 입도가 제각각이면 의미가 약화됩니다. 단독으로는 개선안 도출이 어렵습니다.
- 빈도 ★★★☆☆ · 효과 ★★★★☆

### #55. DMAIC (Six Sigma DMAIC)
- 한 줄: 데이터 기반으로 프로세스 결함을 줄이는 식스시그마의 핵심 개선 사이클입니다.
- 쓸 때: 불량률·결함률이 높은 제조·서비스 공정 개선; 처리 시간·비용의 변동을 줄여야 할 때; 근본 원인이 불명확한 만성 품질 문제; 개선 효과를 정량적으로 입증해야 할 때
- 뼈대: Define · 문제·목표·범위 정의 / Measure · 현재 성능 측정 / Analyze · 근본 원인 분석 / Improve · 개선안 도출·적용 / Control · 개선 상태 유지·관리

- 한계: 데이터 수집·통계 역량이 없으면 형식만 남습니다. 점진 개선에 치우쳐 혁신적 재설계엔 약합니다. 단기 과제에는 절차가 과도하게 무겁습니다.
- 빈도 ★★★★☆ · 효과 ★★★★★

### #56. 린 7대 낭비 (Lean Seven Wastes (TIMWOOD))

- 쓸 때: 생산·물류 현장의 비용 구조 진단; 리드타임 단축과 재고 절감; 사무·서비스 업무의 비효율 발굴; 개선 활동(카이젠) 착수 전 현황 파악
- 뼈대: 운송(Transport) · 불필요한 이동 / 재고(Inventory) · 과잉 보유 / 동작(Motion) · 불필요한 작업 동작 / 대기(Waiting) · 지연·정체 / 과잉생산(Overproduction) · 수요 초과 생산 / 과잉가공(Over-processing) · 불필요한 공정 / 불량(Defects) · 결함·재작업

- 한계: 낭비 제거에 집중하다 인력·재고 여유를 과도하게 줄일 수 있습니다. 비정형 지식노동에는 적용이 모호합니다. 근본 원인 분석 없이 증상만 제거하기 쉽습니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆

- 뼈대: 자재 흐름 · 단계별 물자 이동 / 정보 흐름 · 주문·생산 지시 / 프로세스 박스 · 각 공정 단계 / 데이터 박스 · 사이클타임·재고·가동률 / 타임라인 · 가치/비가치 시간 합산
- 단계: 대상 제품군과 흐름 범위를 정합니다. → 현장을 따라가며 현재 상태 지도를 그립니다. → 단계별 시간·재고·정보 흐름을 기록합니다. → 가치 비율과 병목을 계산합니다. → 낭비를 제거한 미래 상태 지도를 설계합니다. → 두 지도의 격차로 개선 과제를 도출합니다. → 실행 계획과 책임자를 정해 추진합니다.
- 한계: 반복·대량 흐름에 맞고 다품종 소량엔 복잡해집니다. 작성에 시간과 현장 경험이 필요합니다. 지도만 그리고 실행으로 잇지 못하면 무의미합니다.

### #59. 5S (5S (Workplace Organization))

### #60. 칸반 (Kanban)

- 쓸 때: 업무 진행 상황을 한눈에 보고 싶을 때; 병목과 적체를 드러내 흐름을 개선할 때; 동시 작업이 많아 멀티태스킹이 과한 팀; 점진적 변화로 일하는 방식을 개선할 때
- 뼈대: 칸반 보드 · 작업 흐름의 단계 표현 / 카드 · 개별 작업 항목 / WIP 제한 · 단계별 동시 작업 상한 / 풀 방식 · 여유가 생길 때 당겨오기 / 흐름 지표 · 리드타임·처리량
- 단계: 현재 작업 흐름의 단계를 정의합니다. → 단계를 열로 한 보드를 만듭니다. → 진행 중인 일을 카드로 올립니다. → 단계별 WIP 상한을 설정합니다. → 여유가 생기면 다음 일을 당겨옵니다. → 적체 지점을 찾아 흐름을 개선합니다. → 지표를 보며 점진적으로 조정합니다.

### #61. 제약 이론 (Theory of Constraints (TOC))
- 한 줄: 전체 성과를 결정하는 가장 약한 제약에 집중해 처리량을 끌어올리는 이론입니다.
- 쓸 때: 생산·공급망의 처리량을 늘려야 할 때; 여러 개선 과제 중 우선순위를 정할 때; 병목 공정이 전체 납기를 좌우할 때; 부분 최적화의 함정을 피하고 싶을 때
- 뼈대: 제약(Constraint) · 성과를 가로막는 병목 / 처리량(Throughput) · 판매로 버는 속도 / 재고(Inventory) · 묶여 있는 투자 / 운영비용(Operating Expense) · 전환 비용 / 집중 5단계 · 개선의 반복 절차
- 단계: 시스템의 제약(병목)을 찾아냅니다. → 제약을 최대한 활용할 방법을 정합니다. → 나머지 자원을 제약에 종속시킵니다. → 그래도 부족하면 제약 능력을 늘립니다. → 제약이 해소되면 다음 제약을 찾습니다. → 관성에 빠지지 말고 절차를 반복합니다.
- 한계: 제약을 잘못 짚으면 개선이 헛돕니다. 회계·평가 체계가 처리량 관점과 충돌할 수 있습니다. 제약이 자주 이동하는 환경엔 적용이 까다롭습니다.
- 빈도 ★★★☆☆ · 효과 ★★★★☆

### #62. 코터 8단계 변화관리 (Kotter 8-Step Change Model)
- 한 줄: 대규모 조직 변화를 8단계로 추진하는 변화관리 모델입니다.

- 뼈대: 위기감 조성 (Urgency) / 변화 주도 연합팀 구축 / 비전과 전략 수립 / 비전 전파와 소통 / 권한 위임과 장애물 제거 / 단기 성과 창출 / 성과 굳히기와 가속화 / 새로운 문화로 정착
- 단계: 시장과 경쟁 현실을 근거로 변화의 위기감을 조성합니다. → 변화를 이끌 영향력 있는 인물로 주도 연합팀을 구성합니다. → 변화의 방향을 담은 명확한 비전과 전략을 수립합니다. → 모든 채널을 활용해 비전을 반복적으로 전파합니다. → 변화를 가로막는 구조와 장애물을 제거하고 권한을 위임합니다. → 6~18개월 내 보이는 단기 성과를 의도적으로 만들어냅니다. → 단기 성과를 발판으로 더 큰 변화로 가속화합니다. → 새로운 방식을 조직 문화와 제도로 정착시킵니다.
- 한계: 톱다운 순차 모델이라 빠르게 변하는 환경에는 경직될 수 있습니다. 8단계를 모두 거치는 데 시간이 오래 걸립니다. 구성원의 자발적 참여보다 추진력에 치우치기 쉽습니다.

### #63. ADKAR 변화관리 모델 (ADKAR Model)
- 한 줄: 개인 차원의 변화 수용을 5단계로 관리하는 변화관리 모델입니다.
- 쓸 때: 구성원 개개인의 변화 수용도를 점검해야 할 때; 변화가 특정 단계에서 막혀 있는 원인을 진단할 때; 교육과 소통 등 변화 지원 활동을 설계할 때; 코터 모델 같은 전사 변화에 개인 관점을 보완할 때
- 뼈대: 인식 (Awareness) / 욕구 (Desire) / 지식 (Knowledge) / 능력 (Ability) / 강화 (Reinforcement)
- 단계: 변화가 왜 필요한지에 대한 인식을 형성합니다. → 변화에 참여하고 지지하려는 욕구를 끌어냅니다. → 변화에 필요한 지식과 방법을 교육으로 제공합니다. → 실제로 새로운 방식을 수행할 능력을 갖추게 합니다. → 변화가 되돌아가지 않도록 보상과 제도로 강화합니다. → 단계별 진단으로 막힌 지점을 찾아 집중 지원합니다.
- 한계: 개인 단위 모델이라 조직 구조나 전략 변화는 다루지 못합니다. 다섯 단계가 항상 순차적으로 진행되지는 않습니다. 대규모 인원의 단계별 진단에 운영 부담이 큽니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆
- 갤러리 관련: #62 코터 8단계 변화관리, #64 르윈 3단계 변화관리, #45 역량 모델
- 카드: https://strategy.airoasting.com/#63

### #64. 르윈 3단계 변화관리 (Lewin Change Model)
- 한 줄: 변화를 해빙·변화·재동결 세 단계로 설명하는 변화관리 모델입니다.
- 쓸 때: 변화의 전체 흐름을 단순한 틀로 설명해야 할 때; 왜 변화가 정착되지 않고 되돌아가는지 점검할 때; 변화 추진과 안정화의 균형을 설계할 때; 더 상세한 모델에 앞서 기본 구조를 잡을 때
- 뼈대: 해빙 (Unfreeze) / 변화 (Change) / 재동결 (Refreeze) / 추진력과 억제력 (Force Field)
- 단계: 현재 방식의 문제를 드러내 변화의 필요성을 인식시킵니다. → 기존 관행에 대한 안주와 저항을 녹입니다(해빙). → 새로운 방식과 행동을 도입하고 학습시킵니다(변화). → 변화 과정의 추진력은 키우고 억제력은 줄입니다. → 새 방식을 표준과 보상으로 안착시킵니다(재동결). → 변화가 일상 행동으로 굳어졌는지 확인합니다.
- 한계: 변화를 정적인 3단계로 봐서 지속적 변화 환경과 맞지 않습니다. 구체적 실행 방법보다 개념적 틀에 가깝습니다. '재동결'이 빠른 변화 시대에는 오히려 경직성을 낳을 수 있습니다.
- 빈도 ★★★☆☆ · 효과 ★★★☆☆
- 갤러리 관련: #62 코터 8단계 변화관리, #63 ADKAR 변화관리 모델, #58 PDCA 사이클
- 카드: https://strategy.airoasting.com/#64

### #65. 간트 차트 (Gantt Chart)
- 한 줄: 프로젝트 일정을 막대그래프로 시각화하는 일정관리 도구입니다.
- 쓸 때: 프로젝트 전체 일정과 작업 순서를 시각화할 때; 작업 간 선후관계와 일정 중복을 파악할 때; 이해관계자에게 진행 현황을 공유할 때; 마일스톤과 납기를 기준으로 진척을 관리할 때
- 뼈대: 작업 목록 (Tasks) / 시간 축 (Timeline) / 작업 막대 (Bars) / 마일스톤 (Milestones) / 의존관계 (Dependencies) / 진척률 (Progress)
- 단계: 프로젝트를 관리 가능한 작업 단위로 분해합니다. → 각 작업의 소요 기간을 산정합니다. → 작업 간 선후관계와 의존성을 정의합니다. → 시간 축에 작업 막대를 배치해 일정을 구성합니다. → 주요 분기점을 마일스톤으로 표시합니다. → 실제 진척을 막대에 반영해 계획 대비 차이를 관리합니다.
- 한계: 작업이 많아지면 막대가 복잡해져 가독성이 떨어집니다. 어느 작업이 일정을 좌우하는 핵심 경로인지 직접 보여주지 못합니다. 빈번히 변하는 일정은 갱신 부담이 큽니다.
- 빈도 ★★★★★ · 효과 ★★★★☆
- 갤러리 관련: #66 크리티컬 패스, #67 스크럼, #52 프로세스 분해
- 카드: https://strategy.airoasting.com/#65

### #66. 크리티컬 패스 (Critical Path Method (CPM/PERT))
- 한 줄: 프로젝트 최단 완료 기간을 결정하는 핵심 경로 분석 도구입니다.
- 쓸 때: 일정 지연에 직결되는 핵심 작업을 식별할 때; 프로젝트 최단 완료 기간을 정밀하게 산정할 때; 자원을 어느 작업에 집중할지 판단할 때; 일정 단축이나 지연 대응 시나리오를 검토할 때
- 뼈대: 작업 (Activities) / 의존관계 (Dependencies) / 소요 기간 (Duration) / 여유 시간 (Float/Slack) / 핵심 경로 (Critical Path) / 네트워크 다이어그램
- 단계: 모든 작업과 작업 간 의존관계를 정의합니다. → 각 작업의 소요 기간을 산정합니다. → 작업들을 네트워크 다이어그램으로 연결합니다. → 시작부터 끝까지 가장 긴 경로(핵심 경로)를 계산합니다. → 각 작업의 여유 시간을 산출합니다. → 여유가 0인 핵심 경로 작업을 집중 관리합니다. → 일정 단축이 필요하면 핵심 경로를 우선 압축합니다.
- 한계: 소요 기간 추정이 부정확하면 경로 분석 전체가 흔들립니다. 작업이 많아지면 네트워크 계산과 관리가 복잡해집니다. 자원 제약보다 작업 순서에 초점이 맞춰져 있습니다.
- 빈도 ★★★★☆ · 효과 ★★★★☆
- 갤러리 관련: #65 간트 차트, #67 스크럼, #61 제약 이론
- 카드: https://strategy.airoasting.com/#66

### #67. 스크럼 (Scrum)
- 한 줄: 짧은 반복 주기로 제품을 점진적으로 개발하는 애자일 프레임워크입니다.
- 쓸 때: 요구사항이 자주 바뀌는 제품을 개발할 때; 짧은 주기로 결과물을 내고 피드백을 반영할 때; 자율적인 소규모 팀으로 일을 운영할 때; 불확실성이 높아 계획을 단계적으로 구체화할 때
- 뼈대: 프로덕트 오너 (PO) / 스크럼 마스터 / 개발팀 / 제품 백로그 / 스프린트 백로그 / 스프린트 (Sprint) / 스크럼 이벤트(데일리·리뷰·회고)
- 단계: 프로덕트 오너가 우선순위로 정렬된 제품 백로그를 관리합니다. → 스프린트 계획 회의에서 이번 주기의 작업을 선정합니다. → 1~4주 단위 스프린트로 작동하는 결과물을 개발합니다. → 매일 데일리 스크럼으로 진행 상황을 공유합니다. → 스프린트 리뷰에서 결과물을 이해관계자에게 시연합니다. → 회고를 통해 팀의 일하는 방식을 개선합니다. → 다음 스프린트로 주기를 반복합니다.
- 한계: 역할과 이벤트 규율이 무너지면 형식만 남기 쉽습니다. 일정과 범위가 고정된 프로젝트에는 맞지 않습니다. 대규모 조직으로 확장할 때 추가 체계가 필요합니다.
- 빈도 ★★★★★ · 효과 ★★★★☆
